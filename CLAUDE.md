## Quizzes (encrypted, released on time)
The repo is public, so quiz questions are committed only encrypted; a time check in JavaScript would hide nothing.
- Files in `teaching/group-theory/quizzes/`: `quizN.html` (page shell: countdown, password box), `quizN.enc.json` (AES-256-GCM ciphertext, salt, IV; key from PBKDF2-SHA256, 600,000 iterations), `quiz.js` (shared loader: polls `quizN.key?t=…` every 15 s, decrypts with WebCrypto, waits for the release time by the server clock), and after release `quizN.key` (the passphrase, which stays so the quiz remains readable).
- Never commit quiz plaintext, not even briefly. Keep it outside the repo (or in the gitignored `_private/`). After any quiz work, check: `git grep -F "<a phrase from the quiz>" $(git rev-list --all)` must print nothing.
- Release: `.github/workflows/quiz-release.yml` reads the passphrase from the quiz's Actions secret, checks it opens `quizN.enc.json` (`_tools/quiz-check.js`), then commits `quizN.key` to `main`; Pages deploys in about 70 s (measured). `lead_seconds` in `.github/quizzes.json` is how early it publishes (150 s); the page itself shows the questions only at the release time.
  - By hand (also from the GitHub mobile app): Actions > "Release a quiz" > Run workflow, quiz id e.g. `quiz2`. Releases at once.
  - Scheduled: runs at :07 and :37 past each hour, 06–16 UTC on weekdays; a run releases the next quiz due within 80 minutes, sleeping until its release time minus `lead_seconds`. Not yet tested end to end; test it before relying on it (see below).
  - Fallback in class: write the passphrase on the board; students type it in the page's password box.
- Adding the next quiz (N = 2, …, 6):
  1. Write the questions as an HTML fragment outside the repo (same classes as Quiz 1: `qmeta`, `qbox`, `h2` with `span.pts`, `ol.parts`).
  2. Choose four random lowercase words; encrypt: `node _tools/quiz-encrypt.js /outside/quizN.html quizN "four random words here"`.
  3. Copy `quiz1.html` to `quizN.html` and change `data-id`, `data-name`, `data-opens` (UTC ISO time), `data-opens-label`, the title, `h1` and the date line.
  4. Add `{ "id": "quizN", "secret": "QUIZ_N_KEY", "release": "<UTC ISO time>" }` to `.github/quizzes.json` and the secret `QUIZ_N_KEY` (the passphrase) under Settings > Secrets and variables > Actions. Secrets QUIZ_1_KEY … QUIZ_6_KEY are wired into the workflow.
  5. Link it from its week in `GT` (`assets/site.js`) with `quizUrl` and `quizWhen`, raise the asset version, commit, and run the plaintext check above.
- Turkey is UTC+3 all year: 14:30 Istanbul = 11:30 UTC, 13:30 = 10:30 UTC.

- Two ungraded practice quizzes: Practice quiz 1, Tuesday 13 October 2026, `teaching/physics-1/quizzes/practice.html` (`data-id="phys-quiz1"`, sheet tab "Quiz 1"), symbolic solutions in `practice-solutions.html`; Practice quiz 2, Tuesday 20 October 2026, `practice2.html` (`data-id="phys-q1"`, sheet tab "Quiz 1 (20 Oct)"), projectile motion, meant as the graded Quiz 1 but not graded because the version 1 backend could not serve the whole class at once; solutions (symbols and numbers) in `practice2-solutions.html`. Graded quizzes: Quiz 1 to Quiz 6 plus a make-up quiz, as listed in `PHYS`. Quiz 1: Tuesday 27 October 2026, `quiz1.html` (`data-id="phys-q1-27oct"`), Start open 14:30–14:45, applying Newton's laws (block sliding down a rough ramp, symbols only), version 2 backend, sheet tab "Quiz 1 (27 Oct)". A `PHYS` quiz entry is `[name, when, page url, solutions url]`; the last two are added once they exist, and each quiz gets its own Solutions chip. Use a new tab name (`QUIZ.sheet`) and a new `data-id` for every quiz so results never mix.
- Page: `teaching/physics-1/quizzes/quizN.html` plus the shared `live-quiz.js` (attributes `data-name`, `data-opens`, `data-closes` and their `-label` versions set the before/open/closed messages). The page holds NO questions: `data-endpoint` is the Apps Script web app URL, `data-opens` the opening time (UTC). Students enter their student number, confirm, get 10 minutes from their own Start and answer the parts in order: tapping a choice only selects it (it can be changed); "Submit answer" then "Yes, submit" sends it, and only then the page shows whether it was right, the correct answer and the solution. A choice still unsubmitted at 0:00 does not count (a warning shows in the last minute). A reload resumes the same attempt (student number kept in localStorage; "Use another student number" forgets it on a shared device). The page sends one request at a time and retries a busy or unreachable server with random backoff for 2 minutes; it takes its clock from the server (one GET when it opens), hides the Start box only 2 minutes after `data-closes` by the server's clock, and at 0:00 stops taking answers and shows the result itself. Pages load `live-quiz.js?v=4`: raise N in every quiz page after changing it.
- Backend: a Google Apps Script bound to the Google Sheet "Physics I quizzes" in the owner's Google account. Its `QUIZ` object holds the questions, choices, answers, solutions, opening time, last start time and length; it grades on the server, allows one answer per part and enforces the times by its own clock. Quiz 1 (20 October) ran on version 1, which made every request wait for one lock and write the sheet; it served about one request per second and many students could not start. Version 2 (from Quiz 2) keeps each student's record in a script property, so requests never wait for each other, and copies the records to the sheet tab named in `QUIZ.sheet` about every 30 s (and when the spreadsheet is opened, from the menu Quiz > Update results now, and by a one-time trigger after the quiz). Only numbers on the class list (`CLASS_LIST` in the script) can start. One secret test number, set in `QUIZ.testIds` in the private script and never written in this repo, works at any time and starts afresh. Never commit that script, the class list or the test number to this public repo.
- Before every quiz and after any change to the script: paste it into an EMPTY editor (code pasted inside the default `function myFunction() {` hides doGet/doPost; keep one .gs file), run `checkSetup` in the editor (accept the permissions; its log must end with "Ready"), then Deploy > Manage deployments > edit (pencil) > Version: New version > Deploy (the URL stays the same), then open the web app URL in a private window and try the quiz page with the test number. During a quiz, never save in Project Settings > Script properties.
- Next quiz: give the owner an updated script (new `QUIZ` block with a new `sheet` name, and the class list; earlier results stay in their tabs); copy `quiz1.html` to `quizN.html` and change `data-id`, `data-opens`, `data-opens-label`, `data-closes`, `data-closes-label`, `data-endpoint` if it changed, the title, `h1` and date line; link it from its topic in `PHYS` (`assets/site.js`) as the third element of the quiz entry, e.g. `["Quiz 1","Tuesday 20 Oct, 14:30","quizzes/quiz1.html"]`; raise the asset version.

## Group theory conventions (match the lecture slides)
- Triangle vertices labeled 1, 2, 3 counterclockwise from the bottom left; `r` = counterclockwise turn by 2π/n; `s` = reflection in the line through vertex 1.
- Products read right to left: in `ab`, `b` acts first. Cycle (123) sends 1 to 2, 2 to 3, 3 to 1.
- Normal form for dihedral elements: `r^k` or `r^k s`.
